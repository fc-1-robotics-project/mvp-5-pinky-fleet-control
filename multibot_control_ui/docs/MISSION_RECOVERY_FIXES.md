# 임무 대기·복구·위치 판정 수정 (2026-10-09)

두 저장소의 최신 `origin/develop`에서 `feature/mission-recovery-position-20261009`를 만들었다.
로봇 기준 커밋은 `4cef4d9`, 관제 최초 기준 커밋은 `3cbdde2`였으며, 최신 `origin/develop`의 `7a84a49`로 리베이스했다.

## 변경된 동작

- 장애물·clear hold·횡단보도 대기는 최신 진단과 명령 사유, 차선·센서 정상 상태가 일치할 때만 의도적 대기로 인정한다. 이 대기를 15초 정체로 종료하지 않는다. 설명 없는 제로 명령, 센서/차선 이상, 허가 소실, 이동 명령에도 진행하지 않는 상황은 기존 감시를 유지한다.
- 운영자·병목·복구 HOLD에서는 Nav2 목표를 보존하고 기존 액션 취소를 요청한다. 승인 대기 중인 목표도 승인 직후 취소한다. 실제 액션 결과 전에는 RUN이나 중복 목표를 보내지 않는다. 성공한 목표는 다시 보내지 않고 운영자 중단·ESTOP은 자동 재개하지 않는다.
- 개별 임무 실패는 해당 로봇을 복구한다. 병합된 로봇별 복구 구조를 유지하여 개별 상태 지연도 해당 로봇만 복구한다. 병목 소유자의 위치가 오래돼 공유 점유를 확정할 수 없으면 전체 HOLD하며 소유권을 보존한다.
- 수동 선택 중에는 저장 Nav2 목표를 자동 재전송하거나 NAV2 모드로 복원하지 않는다. 기존 Nav2 취소 결과 전에는 HOLD/종료 확인 중으로 안내하고, 수동 해제 후 미완료 목표만 한 번 재개한다.
- 부분 복구는 각 로봇의 주행 모드를 복원한 뒤 복구 완료로 표시한다. 다른 로봇의 정리가 지연돼도 재개된 로봇의 성공·재실패를 처리하며, 새 실패는 다시 HOLD·재시도 대상으로 등록한다.
- `/fleet/pose`의 header는 TF 원본 시각이다. 로봇은 무효·미래·오래된 TF를 발행하지 않고, 관제는 원본 시각과 수신 시각 모두 검사하고 최신 develop의 최대 100ms 앞섬 허용값을 유지한다. 마지막 AMCL 공분산은 정지 중 유지될 수 있으며 새 TF마다 공분산을 재측정했다고 해석하지 않는다. 로봇과 관제의 시각 동기화는 필요하다.
- 시연 시작의 위치 분산 허용값은 x/y 각각 0.30m², 차선 자동 종료는 `lane_exit_position_variance`의 기본 0.0025m²(표준편차 5cm)로 구분한다. 종료 반경 0.20m·유지 시간 0.5초와 기존 yaw 상한은 유지한다.

인터페이스 정의, 속도·watchdog·센서 임계값, Nav2 progress checker는 변경하지 않았다.
횡단보도 정지 기능을 활성화하는 운용 설정 변경은 포함하지 않았다.

## 검증 범위

새 회귀 테스트를 수정 전 코드에서 실패시키고 구현 후 다시 실행했다.
리베이스 전 로봇 fast 157개, 관제 오프라인 동작 검사 184개가 통과했다(관제 기존 lint 3개 제외).
로봇은 의존성 포함 7개 패키지 빌드 및 영향 패키지 검사 29개(실패 0, skip 1),
관제는 `pinky_interfaces`·`vision_control`·`multibot_control_ui` 빌드를 통과했다.
localhost domain 177의 ROS dry-run 검사 33개도 통과했다. 종료 뒤 Destroyable
정리 경고가 출력됐으며 실행 종료 코드는 0이었다.
검사 명령과 안전 검토 기록은 로봇 저장소의 `.agents/output/harness/`에 보존한다.
독립 안전 검토는 1차 지적 수정 후 PASS 판정을 받았다(하드웨어 없는 코드·ROS 범위).
안전 검토에서 HOLD 중 입구 Nav2가 성공한 뒤 차선 단계에 중단 표시가 남는 오류를
발견해 수정했으며, 취소 대기부터 차선 재개까지 연결한 회귀 검사를 추가했다.
추가 부작용 점검에서 수동 선택 덮어쓰기와 부분 복구 모드/재실패 처리 오류를 발견해
수정했다. 두 수동 API·취소 결과 도착 순서·부분 복구 후 완료/재실패/전역 건강 이상 및
명시적 취소·새 목표를 연결한 회귀 16개를 추가했다. 전체 184개 검사와 관제 3개 패키지 재빌드가 통과했다.
추가 부작용 수정의 독립 안전 재검토도 PASS를 받았다(`05_side_effect_fix_review.md`).

취소가 거부되거나 전송/결과 상태를 확인할 수 없으면 HOLD를 유지한다. 이 경우
서버 상태와 STOP을 확인한 뒤 운영자가 조치해야 하며 자동 재전송으로 해결하지 않는다.

Gazebo와 실로봇 시험은 수행하지 않았다. 과거 통합 시연의 전체 완주 미확인 기록은
[두 로봇 통합 시연](TWO_ROBOT_DEMO.md)의 2026-10-06 현장 기록에 보존한다.
