# 두 로봇 통합 시연

개발 브랜치: `feature/mission-recovery-position-20261009` (`origin/develop` 기반).
기준일: **2026-10-09**. 로봇별 복구와 긴 복구 대기의 Nav2 취소·재시도를 구현했다. 현재 수정은 오프라인 검증 범위이며 실제 전체 통합 시연 완주는 미확인이다. 2026-10-06 현장 결과는 아래에 이전 버전 기록으로 남긴다.

현재 검증: 기능 테스트 **231개 통과**(lint 3개 제외), 실제 PC 작업공간 **3개 패키지 빌드 성공**. 최신 `origin/develop`의 `7a84a49` 위에서 검사했다. 원본 시각 허용값 0.1초를 유지하고 source/receive age를 함께 검사한다. 검증 중 UI·주행 노드는 실행하지 않았고 하드웨어 주행 결과는 없다.

## 흐름

1. A는 차선 출발, B는 STOP/HOLD 대기.
2. A의 차선 종료 조건 충족 → 기존 종료 Bool → FollowLane 성공 및 STOP·로컬 허가 OFF 확인. 현재 AMCL을 유지한다. 설정된 출구 좌표로 초기 위치를 덮어쓰지 않는다.
3. A/B가 각각의 Nav2 waypoint를 순서대로 방문한다. 각 점의 NavigateToPose 성공을 도착으로 인정해 다음 점을 보낸다. 관제에서 위치/방향 오차를 다시 검사하지 않는다.
4. **두 로봇 모두** 확정된 waypoint 목록을 마치면 A는 Nav2 최종 목적지, B는 차선 입구로 이동한다. B는 입구 NavigateToPose 성공 후 차선 주행을 시작한다. 차선 시작 점검과 주행 허가 확인은 유지한다.
5. B는 동일한 차선 종료 규칙으로 정지한다. A/B 최종 완료 시 전체 관제 HOLD. 개별 목표 취소·시연 중단은 두 시연 임무를 취소하고 STOP/HOLD한다. 통신·위치 정보 지연, 액션 실패, 구간 시간 초과는 해당 로봇의 목표와 진행 단계를 보존한 복구 대기로 전환한다. 정상 로봇은 기존 병목 허가와 단계 조건 안에서 계속 진행한다. 비상정지는 ESTOP을 유지하며 시연 요청을 즉시 취소한다. 비상정지로 취소한 시연은 관제 RUN만 눌러도 자동 재개되지 않는다.

병목 소유권 계산은 기존 FleetCoordinator를 사용한다. 사전 예약이나 A/B 고정 우선권은 추가하지 않는다. 임무 사이 대기점은 병목·연결 통로 밖에 배치해야 한다. 한 로봇이 통로 안에서 다른 로봇의 목록 완료를 기다리는 배치는 교착을 만들 수 있다.

## UI 설정·실행

기존 로봇 통합 launch와 PC 관제 launch를 사용한다. 별도 시험 스크립트는 필요 없다.

1. 두 로봇을 활성화하고 같은 지도를 사용한다. 기존 UI에서 실제 초기 위치·방향과 병목 구역을 설정한다. 로봇 STOP·로컬 허가 OFF, 새 상태 정보 수신을 확인한다.
2. 메인 UI의 **두 로봇 통합 시연 → 통합 시연 설정 · waypoint 편집** 버튼으로 설정 창을 연다. A/B 로봇과 차선 `route_id`를 지정한다.
3. A 차선 끝/Nav2 합류, A 최종 목적지, B 차선 입구, B 차선 끝 좌표를 각 행의 **지도 선택 → 클릭·드래그 → 좌표 반영**으로 입력한다. yaw 단위는 도(degree), 위치는 m다. 특히 B 입구 yaw는 차선 진행 방향으로 지정한다.
4. A/B별 waypoint를 지도에서 입력해 **대기점 추가**한다. 대기점은 선택점 수정·선택점 삭제·위로/아래로 이동이 가능하다. 각 목록을 다 만들면 **목록 끝에서 다음 단계 진행**을 체크한다. **설정 저장**을 누른 뒤 메인 UI에서 현장 확인을 체크하고 **통합 시연 시작**을 누른다. 설정 창을 닫아도 저장된 설정으로 시작할 수 있다.
5. 주행 중에도 아직 전송되지 않은 목록을 수정할 수 있다. 현재 목표는 자동 교체하지 않는다. 확정하지 않은 목록이 비면 STOP/HOLD로 추가 입력을 기다린다. 해당 로봇이 목록 완료를 확정한 뒤에는 그 목록을 다시 열지 않는다.

메인 UI의 통합 시연 영역에서 **시연 일시정지/재개**, **시연 중단**과 진행 상태를 확인한다. 설정 창에는 설정 불러오기·저장과 편집 기능만 둔다. 시작은 항상 마지막으로 저장된 파일을 읽으며, 저장하지 않은 편집은 다음 실행에 반영되지 않는다. 고정 좌표를 수정한 뒤 **좌표 반영**을 누르지 않으면 저장을 거부하고 해당 항목을 안내한다. 실행 중에는 고정 설정과 파일 저장/불러오기를 비활성화하고, 아직 완료하지 않은 Nav2 대기 목록만 편집할 수 있다. 비상정지와 수동 차선 구간 완료는 기존 본창 버튼을 사용한다. 시연 중 개별 Nav2 목표·차선 시험·수동 조작 전환은 중복 임무 방지를 위해 거부한다. 수동 조작은 시연 중단 후 전환한다. 시연 중 개별 일시정지는 비활성화하며, 선택 임무 취소는 **통합 시연 중단 (두 대)**로 표시한다. 본창의 「선택 로봇 임무 / 차선 시험」에서 개별 차선 시험과 완료·일시정지·중단을 사용한다. 기존 3개 pose 입력과 「연속 임무 시작」은 UI에서 제거했으며 연속 주행은 통합 시연 창에서 설정한다.

설정은 `~/.config/pinky_fleet_control/two_robot_demo.json`에 명시적으로 저장한다. 기존 `lane_routes.json`과 분리되어 있다. 지도 해시가 다르면 시작을 거부한다. 주행 중 편집은 현재 실행의 대기 목록에 적용되며 저장된 재실행 설정을 자동 덮어쓰지 않는다.

## 시연 시작 조건과 초기 위치

| 조건 | 현재 기준 |
|---|---|
| 현장·설정 | 두 로봇 배치/감시 확인 체크, 서로 다른 A/B, 저장된 설정과 지도 일치 |
| 운용 상태 | 비상정지·수동 조작·다른 임무 없음, 두 로봇 STOP·로컬 허가 OFF·이전 임무 정리 완료 |
| 통신·위치 | 최신 heartbeat/로봇 상태, 원본·수신 지연 각각 1.5초 이내의 map 위치, 원본 시각의 최대 100ms 앞섬 허용, 유한한 좌표와 정상 quaternion |
| 위치·방향 분산 | x/y 각각 **0.30m² 이하**(표준편차 약 55cm), yaw **20° 표준편차 이하**(약 0.122rad²) |
| 차선 시작 | A 로봇의 기존 카메라·차선·센서·명령/허가 점검이 ready |

기존 시연은 UI initial pose의 기본 위치 분산 **0.25m²**를 보내면서도 **0.04m² 이하**만 시작을 허용했다. 지도에서 실제 위치·방향을 지정한 직후 불필요하게 시작이 막힐 수 있어 위의 유한한 범위로 완화했다. yaw의 기존 상한은 0.07rad²(표준편차 약 15.2°)였다. AMCL이 실제 보고한 분산이나 UI가 보내는 initial pose 값을 작게 덮어쓰지는 않는다.

시연 시작·주행 중 위치 유효성은 위 분산 기준을 사용한다. 자동 차선 끝 검사에는 더 엄격한 x/y 분산 `lane_exit_position_variance`(기본 0.0025m²)를 적용한다. 시작만 허용한 뒤 이전 분산 상한 때문에 즉시 복구 대기에 들어가지 않는다. 신선도·좌표계·비정상 값·과도하게 큰 분산은 계속 검사한다. 로봇 상태와 `/fleet/pose`의 원본 시각이 PC보다 최대 100ms 앞서는 작은 시계 차이는 허용한다. 원본이 1.5초보다 오래되거나 100ms보다 앞서면 거부하며, 수신 지연도 별도로 1.5초 이내여야 한다. 한 번 실패하면 공통 「AMCL 확인 필요」 대신 heartbeat, 로봇 상태, STOP, 로컬 허가, 정리 상태, 위치/방향 분산 중 실제 막힌 항목을 UI에 표시한다.

조절 위치는 `demo_mission.py`의 `POSE_POSITION_VARIANCE_LIMIT=0.30`, `POSE_YAW_VARIANCE_LIMIT=math.radians(20.0)**2`다. 기존 개별 연속 임무 API의 엄격한 기본값은 유지한다. 분산 상한 완화는 수동으로 지정한 위치가 실제 위치와 맞음을 대신 검증하지 않으므로, 시연 시작 전 지도 표시와 실제 배치를 대조한다.

## A/B 차선 자동 종료

- AMCL이 유효하고 차선 끝의 **반경 0.20m 이내에서 0.5초** 도착이 확인되면 종료 Bool을 요청한다. 끝 지점 yaw는 종료 반경 판정에 사용하지 않는다.
- 차선이 보이거나 로봇이 움직이는 중에도 도착을 인정한다. 차선 소실 또는 실제 3초 정지는 필수 조건이 아니다. 종료 Bool 뒤 로봇의 STOP·로컬 허가 OFF·액션 성공을 확인한 뒤에만 다음 단계로 진행한다.
- AMCL 반경 이탈, 상태 메시지 오래됨, 관제 HOLD, 일시정지, 수동 모드, 장애물 정지·clear hold, 비상정지는 도착 확인 시간을 초기화한다. 일시적인 영상/센서 지연은 시간을 지우지 않지만, 최신 센서 상태가 정상으로 돌아오기 전에는 종료 요청을 보내지 않는다.
- 기존 센서/명령 제한을 유지한다. 기존 5Hz `/fleet/pose`(AMCL 공분산 + 신선한 localization TF)의 원본·수신 지연 상한은 각각 1.5초이며, 원본 시각의 최대 100ms 앞섬만 허용한다. 자동 차선 끝의 공분산 상한은 x/y 각각 0.0025m², yaw 약 0.122rad²다. 시연 시작·건강 검사의 x/y 0.30m²와 구분한다. 로봇과 PC 시각 동기화가 필요하다.
- AMCL·heartbeat·로봇 상태 유효성 상실은 시연을 종료하지 않고 복구 대기로 전환한다. 차선 정리 또는 완료 응답이 5초를 넘으면 동일한 완료 요청과 STOP·허가 OFF를 다시 확인한다. 확인 전에는 다음 모드로 넘어가지 않는다.

## 오류 후 재검사·재시도

- UI에 현재 단계와 로봇별 **복구 대기** 사유를 표시한다. 해당 로봇만 STOP/HOLD로 대기하며 현재 목표·대기 waypoint·완료 목록·병목 소유권을 유지한다. 정상 로봇의 목표 완료와 다음 waypoint 진행은 계속 처리한다. 병목 경계의 HOLD와 두 목록 완료 후 FINAL로 가는 단계 조건은 그대로 적용한다.
- 해당 로봇의 heartbeat, 브리지 위치, 유효한 AMCL, 로봇 상태가 **1초 동안 정상**으로 확인되면 복구를 검사한다. 목표 재전송과 종료 Bool 재전송은 **최소 3초 간격**으로 한다. 다른 로봇의 오류가 이 정상 확인 시간을 초기화하지 않는다.
- 복구 HOLD가 **3초 이상** 지속되면 해당 로봇의 실행 중인 Nav2 액션 취소를 요청하고 목표를 보존한다. 취소 요청의 승인·오류만으로 종료를 판단하지 않고 액션 종료 결과를 기다린 뒤 해당 목표만 재시도한다. 복구 중 도착 성공이 확인된 목표와 정상 로봇의 성공한 목표는 재전송하지 않는다. Nav2 도착은 항상 NavigateToPose 성공을 기준으로 한다.
- 차선 액션 실패 시 로봇이 STOP·로컬 허가 OFF·cleanup 완료·시작 준비 상태임을 확인한 뒤 같은 방향의 차선 구간을 새 임무로 재시도한다. 차선 종료 요청 중 응답이 늦으면 해당 임무의 종료 Bool을 다시 보내며, 완료된 같은 임무의 COMPLETE·STOP·허가 OFF 보고로 늦거나 잃어버린 성공 응답을 복구할 수 있다. 다른 임무의 완료 보고는 사용하지 않는다.
- 구간의 15분 제한 시간은 시연 전체 종료 대신 해당 구간 취소 확인 후 재시도에 사용한다. 상태가 계속 비정상이면 복구 대기를 유지하며 성공으로 간주하거나 다음 구간을 건너뛰지 않는다. 운영자의 전체 일시정지는 두 로봇을 HOLD하고 **시연 재개**를 기다린다. **시연 중단·개별 취소·비상정지**는 운영자의 명시적 종료이므로 자동 복구하지 않는다. 병목 점유 로봇의 위치가 늦어 소유권이 불확실하면 기존 소유자와 lease를 유지하고 **두 로봇 모두 STOP/HOLD**한다. 점유 로봇의 위치가 다시 유효해진 뒤 복구를 검사한다.

## 변경 범위와 적용 순서

이번 수정은 PC의 `multibot_control_ui`(로봇별 복구·Nav2 취소 및 재시도·위치 신선도·종료 분산), `vision_control`(원본 시각 검사)에 적용한다.
로봇 쪽 의도적 대기·TF 원본 시각 보존 보완은 별도 lane-driving 저장소의 같은 feature 브랜치에 있다. [수정 기록](MISSION_RECOVERY_FIXES.md)을 참고한다.
인터페이스 `.msg/.action`, domain bridge 토픽, 차선 조향/속도 설정, 병목 점유 계산은 변경하지 않는다.

통합 시연 최초 설치 시에는 두 로봇에 `exit_status.version=1`을 보고하는 `pinky_lane_driving`이 필요하다. 이 버전이 없는 예전 로봇 상태는 시연 시작을 거부한다. 이미 통합 시연 로봇을 사용 중이면 이번 수정은 PC 두 패키지에 적용한다. 기존 개별 운용 기능은 계속 사용할 수 있다.

```bash
# PC 실행 작업공간
source /opt/ros/jazzy/setup.bash
cd ~/colcon_ws
colcon build --symlink-install --packages-select vision_control multibot_control_ui
source install/setup.bash
```

## 빈 waypoint와 최종 목적지

A/B waypoint는 선택 사항이다. 두 목록이 비어 있어도 양쪽 **목록 끝에서 다음 단계 진행**을 확정하면 A 차선 종료 후 FINAL로 이동한다. 확정하지 않으면 추가 입력을 기다린다.
A의 최종 정지점은 **A 최종 Nav2 목적지**다. 마지막 waypoint는 중간 경유지이며 별도 최종 목적지를 대체하지 않는다. B는 입구 Nav2 성공 후 차선 주행으로 전환하고 B 차선 끝에서 정지한다.

## 이전 버전 현장 확인 (2026-10-06)

아래 결과는 로봇별 복구 수정 전 `codex/two-robot-demo-20261005`의 현장 기록이다. 현재 브랜치의 실제 주행 결과가 아니다.

| 확인 내용 | 당시 판단 |
|---|---|
| A 최종 Nav2 전송 | 정상 전송됐으나 최종 NavigateToPose 성공은 기록되지 않음 |
| 첫 복구 대기 | A 로봇 상태 신선도 문제로 두 로봇 HOLD, 약 3초 후 재개 |
| B 차선 전환 후 실패 | `sensor_failure`, `obstacle` 뒤 `ABORTED / LANE_FAILED`. 정확한 액션 중단 사유는 로그만으로 확정하지 못함 |
| A 조기 정지 | B 실패의 **전체 복구 대기**가 A도 STOP/HOLD. B 준비가 돌아오지 않으면 A도 재개 못함 |
| 추가 Nav2 현상 | 의도적 HOLD 중 액션이 유지되어 progress 검사 실패 반복. planner `worldToMap failed` 다수 발생은 별도 원인 분석 필요 |

관제 추가 도착 거리 검사로 멈춘 것은 아니다. 당시 현장 Nav2 progress checker는 10초에 50cm 이동을 요구해 전체 HOLD와 충돌할 수 있었다. `worldToMap failed`는 지도 밖 셀 처리 오류이며 최종 목표 자체가 지도 밖이라는 증거는 아니다.

현재 브랜치에는 이 기록을 바탕으로 **로봇별 임무 복구 분리**와 **긴 복구 HOLD에서 목표 보존 후 Nav2 액션 종료·재전송**을 구현했다. 병목 점유 위치 불확실성의 전체 HOLD와 운영자 일시정지·비상정지는 유지한다. 이번 수정의 검증은 오프라인 범위이며, 위 현장 오류의 실제 해소나 전체 완주를 확인한 결과는 아직 없다.
시험 후 사용자가 로봇 프로그램을 종료하고 UI를 재실행했다. 이후 shutdown의 lifecycle/process 오류를 최초 주행 정지 원인과 구분한다.
