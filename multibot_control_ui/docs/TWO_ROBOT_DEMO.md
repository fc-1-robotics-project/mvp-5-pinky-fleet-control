# 두 로봇 통합 시연

개발 브랜치: `codex/two-robot-demo-20261005` (팀 `develop` 기반).
실제 로봇 미적용: 이 문서의 흐름은 로컬 모의 클라이언트로 검증했으며 현장 주행 검증은 별도다.

## 흐름

1. A는 차선 출발, B는 STOP/HOLD 대기.
2. A의 차선 종료 조건 충족 → 기존 종료 Bool → FollowLane 성공 및 STOP·로컬 허가 OFF 확인. 현재 AMCL을 유지한다. 설정된 출구 좌표로 초기 위치를 덮어쓰지 않는다.
3. A/B가 각각의 Nav2 waypoint를 순서대로 방문한다. 각 점의 NavigateToPose 성공과 실제 도착 위치/방향을 확인한 뒤 다음 점을 보낸다.
4. **두 로봇 모두** 확정된 waypoint 목록을 마치면 A는 Nav2 최종 목적지, B는 차선 입구로 이동한다. B는 입구 위치/방향 도착 확인 후 차선 주행을 시작한다.
5. B는 동일한 차선 종료 규칙으로 정지한다. A/B 최종 완료 시 전체 관제 HOLD. 개별 목표 취소·시연 중단·고장은 두 시연 임무를 취소하고 STOP/HOLD한다. 비상정지는 ESTOP을 유지하며 시연 요청을 즉시 취소한다. 관제 RUN만 눌러도 시연이 자동 재개되지는 않는다.

병목 소유권 계산은 기존 FleetCoordinator를 사용한다. 사전 예약이나 A/B 고정 우선권은 추가하지 않는다. 임무 사이 대기점은 병목·연결 통로 밖에 배치해야 한다. 한 로봇이 통로 안에서 다른 로봇의 목록 완료를 기다리는 배치는 교착을 만들 수 있다.

## UI 설정·실행

기존 로봇 통합 launch와 PC 관제 launch를 사용한다. 별도 시험 스크립트는 필요 없다.

1. 두 로봇을 활성화하고 같은 지도를 사용한다. 기존 UI에서 실제 초기 위치·방향과 병목 구역을 설정한다. 로봇 STOP·로컬 허가 OFF, 새 상태 정보 수신을 확인한다.
2. 메인 UI의 **두 로봇 통합 시연 → 통합 시연 설정 · waypoint 편집** 버튼으로 설정 창을 연다. A/B 로봇과 차선 `route_id`를 지정한다.
3. A 차선 끝/Nav2 합류, A 최종 목적지, B 차선 입구, B 차선 끝 좌표를 각 행의 **지도 선택 → 클릭·드래그 → 좌표 반영**으로 입력한다. yaw 단위는 도(degree), 위치는 m다. 특히 B 입구 yaw는 차선 진행 방향으로 지정한다.
4. A/B별 waypoint를 지도에서 입력해 **대기점 추가**한다. 대기점은 선택점 수정·선택점 삭제·위로/아래로 이동이 가능하다. 각 목록을 다 만들면 **목록 끝에서 다음 단계 진행**을 체크한다. **설정 저장**을 누른 뒤 메인 UI에서 현장 확인을 체크하고 **통합 시연 시작**을 누른다. 설정 창을 닫아도 저장된 설정으로 시작할 수 있다.
5. 주행 중에도 아직 전송되지 않은 목록을 수정할 수 있다. 현재 목표는 자동 교체하지 않는다. 확정하지 않은 목록이 비면 STOP/HOLD로 추가 입력을 기다린다. 해당 로봇이 목록 완료를 확정한 뒤에는 그 목록을 다시 열지 않는다.

메인 UI의 통합 시연 영역에서 **시연 일시정지/재개**, **시연 중단**과 진행 상태를 확인한다. 설정 창에는 설정 불러오기·저장과 편집 기능만 둔다. 시작은 항상 마지막으로 저장된 파일을 읽으며, 저장하지 않은 편집은 다음 실행에 반영되지 않는다. 고정 좌표를 수정한 뒤 **좌표 반영**을 누르지 않으면 저장을 거부하고 해당 항목을 안내한다. 실행 중에는 고정 설정과 파일 저장/불러오기를 비활성화하고, 아직 완료하지 않은 Nav2 대기 목록만 편집할 수 있다. 비상정지와 수동 차선 구간 완료는 기존 본창 버튼을 사용한다. 시연 중 개별 Nav2 목표·차선 시험·수동 조작 전환은 중복 임무 방지를 위해 거부한다. 수동 조작은 시연 중단 후 전환한다. 시연 중 개별 일시정지는 비활성화하며, 선택 임무 취소는 **통합 시연 중단 (두 대)**로 표시한다. 본창의 「선택 로봇 임무 / 차선 시험」에서 개별 차선 시험과 완료·일시정지·중단을 사용한다. 기존 3개 pose 입력과 「연속 임무 시작」은 UI에서 제거했으며 연속 주행은 통합 시연 창에서 설정한다.

설정은 `~/.config/pinky_fleet_control/two_robot_demo.json`에 명시적으로 저장한다. 기존 `lane_routes.json`과 분리되어 있다. 지도 해시가 다르면 시작을 거부한다. 주행 중 편집은 현재 실행의 대기 목록에 적용되며 저장된 재실행 설정을 자동 덮어쓰지 않는다.

## A/B 차선 자동 종료

- AMCL이 유효하고 차선 끝의 **반경 0.07m 이내**일 때만 판단한다. 끝 지점 yaw는 종료 반경 판정에 사용하지 않는다.
- 유효한 최신 영상에서 **왼쪽·오른쪽 차선 모두 없음** → 종료 Bool 즉시 요청.
- 차선이 보이면 반경 안에서 **실제 정지 3초** 후 요청. odom 속도·누적 위치 변화·회전으로 정지를 확인한다. 정지 임계값은 3mm, 0.02rad, 0.003m/s, 0.02rad/s다. 명령 속도 0만으로 정지로 간주하지 않는다.
- 영상 오래됨/형식 오류, odom·scan·TF 오류, 장애물 정지, 횡단보도 대기, 관제 HOLD, 개별 일시정지, 수동 모드, 비상정지는 자동 종료 근거가 아니다. 구역 밖으로 벗어나거나 조건이 깨지면 정지 시간을 초기화한다.
- 1.1초 영상 유효기간과 기존 센서/명령 제한을 유지한다. 기존 5Hz `/fleet/pose`(AMCL 공분산 + 신선한 localization TF)의 source stamp·수신 시각은 1.5초 이내, 기존 위치/방향 공분산 상한(0.04/0.04/0.07)을 사용한다. 로봇과 PC 시각 동기화가 필요하다.
- AMCL 또는 heartbeat 유효성 상실 시 시연을 중단한다. 구간 도착 오차, 차선 정리 실패, 종료 응답 5초 초과도 다음 모드로 넘어가지 않는다.

## 변경 범위와 적용 순서

PC: `multibot_control_ui`(시연 상태 관리·편집 창), `vision_control`(기존 AMCL 검증 읽기 API).
로봇: `pinky_lane_driving`(차선 가시성·실제 정지 상태 보고).
인터페이스 `.msg/.action`, domain bridge 토픽, 차선 조향/속도 설정, 병목 점유 계산은 변경하지 않는다.

두 로봇의 `pinky_lane_driving`을 업데이트/빌드한 뒤 PC 두 패키지를 업데이트/빌드해야 새 시연이 시작된다. 예전 로봇 상태에는 `exit_status.version=1`이 없어 새 시연 시작을 거부한다. 기존 개별 운용 기능은 계속 사용할 수 있다.

```bash
# PC 실행 작업공간
source /opt/ros/jazzy/setup.bash
cd ~/colcon_ws
colcon build --symlink-install --packages-select vision_control multibot_control_ui
source install/setup.bash
# 기존 TEAM_LANE_GUIDE.md / UI_INTEGRATION.md의 관제 launch 실행
```

`demo_mission.py`의 `EXIT_RADIUS_M`, `EXIT_STATIONARY_S`에 합의한 7cm·3초를 둔다. 범위 변경은 현장 검증 후 진행한다.
