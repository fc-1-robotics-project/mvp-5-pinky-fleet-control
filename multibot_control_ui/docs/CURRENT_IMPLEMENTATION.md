# 현재 구현 상태

기준일: **2026-10-09**, 작업 브랜치: **`feature/mission-recovery-position-20261009`**, 기준: 팀 `develop`.
실행은 [UI 사용법](../../UI_INTEGRATION.md), 설치는 [팀 가이드](../../TEAM_LANE_GUIDE.md),
세부 정책은 [두 로봇 통합 시연](TWO_ROBOT_DEMO.md)을 확인한다.

## 구성과 권한

| 장치 | domain | 구성 |
|---|---:|---|
| robot1 | 21 | 센서·Nav2·차선 인식/제어·임무 서버·모드 mux·velocity gate |
| robot2 | 19 | 같은 로봇 스택, 별도 기체 보정 |
| 관제 PC | 22 | UI·시연/병목 정책·bridge. 액션 client는 로봇 domain에 직접 연결 |

두 로봇은 같은 map 좌표계를 사용한다. 로봇 모드는 STOP/NAV2/LANE/MANUAL,
관제 permit은 HOLD/RUN/ESTOP으로 별도 관리한다. RUN만으로 주행하지 않는다.
차선은 추가로 로봇 로컬 허가 lease와 watchdog을 통과해야 한다.
차선 허가는 OFF로 시작하며 명령은 mux→velocity gate→모터 순서로 흐른다.

## 구현된 운용

1. **통합 시연:** A 차선 → A/B 동적 waypoint → A 최종 Nav2 / B 차선 입구 → B 차선 → 전체 HOLD.
2. **Nav2 도착:** waypoint·최종 목적지·B 입구 모두 NavigateToPose 성공을 사용한다. 관제 추가 pose 검사는 없다.
3. **차선 종료:** 최신 위치의 x/y 분산 각각 0.0025m² 이하에서 끝 반경 20cm·0.5초 유지 → 종료 Bool → FollowLane 성공·STOP·로컬 허가 OFF 확인. 시작 시 허용 분산과 구분한다.
4. **차선 단독 시험:** 현재 배치에서 UI로 시작, 실제 출구에서 수동 완료. 종료 후 AMCL을 덮어쓰지 않는다.
5. **병목:** 기존 실제 점유 기반 소유권을 유지한다. 후행 로봇 HOLD, 경계를 벗어나면 해제. A/B 고정 우선권은 없다.

waypoint 없이도 양쪽 목록의 `목록 끝에서 다음 단계 진행`을 확정하면 FINAL로 진행한다.
A 최종 정지점은 A 최종 Nav2 좌표이며 마지막 waypoint와 다르다.
B는 차선 끝에서 정지한다. 통로 안에서 상대 목록 완료를 기다리는 설정은 교착 위험이 있다.

## UI와 저장

설정·waypoint 편집은 별도 창, 시작·일시정지·재개·중단·상태는 메인 UI에 있다.
초기 위치/시연 pose는 지도 클릭·드래그 후 적용 버튼으로 확정한다.
좌우 분할선과 왼쪽 스크롤로 버튼 잘림을 조절한다.

시연 설정은 `~/.config/pinky_fleet_control/two_robot_demo.json`에 저장한다.
지도 해시가 다르면 시작하지 않는다. 실행 중 고정 좌표는 편집할 수 없고 아직 전송하지 않은 waypoint만 변경한다.
예전 `lane_routes.json`은 보존하며 옛 연속 임무 입력 UI는 제거했다.
병목 YAML은 영구 설정, UI에서 그린 사각형은 해당 실행에만 적용된다.

## 시작·복구 기준

- 두 로봇 STOP·로컬 허가 OFF·cleanup 완료, 최신 heartbeat/임무 상태와 map 위치가 필요하다.
- 시연 AMCL source/receive age는 1.5초 이내이며 원본 시각의 최대 100ms 앞섬을 허용한다. x/y 공분산 각각 0.30m² 이하, yaw 표준편차 20° 이하다.
  UI initial pose 분산을 덮어쓰지 않고 실제 막힌 검사 항목을 표시한다.
- 오류 시 단계·목표를 보존하고 1초 정상 확인/3초 시도 간격으로 재검사한다. 개별 임무·상태 오류는 해당 로봇을 HOLD하며, 병목 소유자 위치 지연으로 공유 점유를 확정할 수 없으면 전체 HOLD한다.
- 의도적 HOLD에서는 Nav2 취소를 요청하고 실제 액션 종료를 기다린다. 재개 시 보존한 목표를 한 번 다시 보내며 이미 성공한 목표는 재전송하지 않는다.
- `/fleet/pose`는 TF 원본 시각을 보존한다. 관제는 원본 시각과 수신 시각 모두 검사하며, 재발행만으로 오래된 위치가 최신으로 인정되지 않는다. 공분산은 마지막 AMCL 측정값이며 TF마다 새로 측정한 값이 아니다.
- 운영자 pause는 재개를 기다리고 취소·ESTOP은 자동 복구하지 않는다.
