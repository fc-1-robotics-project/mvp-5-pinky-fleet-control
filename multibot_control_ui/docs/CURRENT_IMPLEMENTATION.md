# 현재 구현 상태

기준일: **2026-10-03**, 공유 브랜치: **`codex/lane-field-20261001`**.
실행 명령은 [UI 사용법](../../UI_INTEGRATION.md), 설치는 [팀 가이드](../../TEAM_LANE_GUIDE.md)를 사용합니다.

## 1. 구성

| 장치 | domain | 구성 |
|---|---:|---|
| robot1 | 21 | 센서·Nav2·차선 인식/제어·임무 서버·모드 mux·velocity gate |
| robot2 | 19 | 같은 로봇 스택, 별도 기체 보정 |
| 관제 PC | 22 | UI·관제 정책·bridge. Nav2/차선 client는 각 로봇 domain에 별도 참가 |

두 로봇은 같은 `map` 좌표계의 지도를 사용합니다. UI 지도는 robot1 우선, robot1 지도가 없으면 robot2를 사용합니다. 방향별 차선 경로 역시 PC의 공용 설정이며 로봇별 독립 경로가 아닙니다.

## 2. 명령 경로

```text
Nav2 controller/behavior -> velocity_smoother -> /cmd_vel_nav_candidate ──┐
차선 제어 -> lane_watchdog -> /cmd_vel_lane_candidate ─────────────────┤
관제 수동 cmd_vel -> bridge -> /cmd_vel_manual_candidate ──────────────┤
                                                                      v
                                                              drive_mode_mux
                                                                      |
                                                             /cmd_vel_candidate
                                                                      |
                  관제 permit ------------------------------> fleet_velocity_gate
                                                                      |
                                                               /cmd_vel -> 모터
```

모드 선택과 관제 permit은 별도입니다. 관제 RUN이 있어도 유효한 모드·명령이 없으면 이동하지 않습니다. 모터 `/cmd_vel`을 관제에서 직접 발행하지 않습니다.

`NavigateToPose`와 `FollowLane` 액션은 bridge에 등록하지 않습니다. UI 프로세스의 per-domain context가 직접 송수신합니다. map·pose·heartbeat·permit·초기 위치·모드 요청·차선 완료 Bool은 bridge를 통합니다. 차선 상태는 `vision_control`의 직접 구독으로 수신합니다.

## 3. 임무와 완료

- 차선 단독 시험: 현재 배치에서 차선 임무 시작 → 명시적 완료 Bool → STOP·로컬 허가 해제. AMCL 위치를 덮어쓰지 않습니다.
- 연속 임무: 저장된 입구로 Nav2 → 차선 임무 → 출구 완료/확인 → 정지·로컬 허가 해제·출구 AMCL 위치 확인 → 다음 Nav2 목표.
- 단순 차선 인식 소실은 정상 완료로 간주하지 않습니다.
- 로봇 임무 서버가 준비 검사·로컬 허가 갱신·주행 정체/고장 감시·종료를 소유합니다. 허가는 갱신이 끊기면 만료됩니다.
- 관제는 임무 취소 완료와 위치 전환을 확인한 뒤 후속 동작을 진행합니다. 연결 소실·센서 오류·속도 초과·정체는 별도 원인으로 표시됩니다.

## 4. UI와 저장

왼쪽은 스크롤 가능한 조작 패널이고 좌우 분할선으로 폭을 바꿉니다. AMCL 두 로봇, 차선 입구·출구·다음 목표에 `지도 선택` 버튼이 있습니다. 지도 입력과 적용 버튼은 분리됩니다. 방향 전환·선택 취소·드래그 중 지도 크기 변경은 진행 중 드래그를 무효화합니다.

`lane_routes.py`는 한 좌표씩 저장할 수 있지만 연속 임무는 세 좌표 모두와 지도 식별값이 맞아야 시작합니다. 위치는 map의 m, 방향은 도 단위입니다. 저장소 위치는 `~/.config/pinky_fleet_control/lane_routes.json`입니다.

## 5. 병목·HOLD·종료

병목은 실제 위치 기반으로 점유자를 정합니다. 후행 로봇은 확장 경계에서 HOLD하며 원인이 해소되면 진행할 수 있습니다. 선행 로봇의 점유 해제에는 차체 반경+여유가 반영됩니다. UI 기본 반경은 0.09m, 추가 여유 0.01m입니다. 로봇 형상이 다르면 재설정합니다.

관제 일시정지는 HOLD, `전체 정지 / 선택 해제`는 긴급 정지 처리입니다. HOLD/수동 조작 동안 차선의 정체 타이머는 의도적 대기를 구분합니다. UI를 닫으면 임무·permit을 정리하고 같은 launch의 bridge도 종료합니다. 강제 종료·통신 소실에는 permit/로컬 허가 TTL이 적용됩니다.

## 6. 공유 설정과 검증

| 항목 | 현재 값/범위 |
|---|---|
| 차선 기본·보완·인식 소실 유지·최대 속도 | 0.06m/s |
| 차선 각속도 상한 / 추종 거리 최소 | 0.6rad/s / 0.10m |
| 차선 물체 자동 정지 / 횡단보도 정지 | 시험 프로필에서 OFF. Nav2 장애물 설정과 별개 |
| 원본 카메라 / YOLO | 640×480 / 448 |
| PC permit 주기 / TTL | 10Hz / 0.5초 |
| 카메라 신선도 / 차선 명령 무응답 | 1.1초 / 0.2초 |
| 일시 차선 소실 | 기존 측정 경로만 최대 1.5초·6cm 범위에서 사용 |

관제 동작 73개와 모의 Tk 화면/지도 입력 검사를 통과했습니다. 로봇 속도 수정은 빌드·단위·격리 ROS 검사까지 완료했습니다. **0.06m/s 및 새로운 장비 조합의 실제 주행은 아직 검증하지 않았습니다.** 데이터 수집용 영상/rosbag/CSV 기록 기능은 추가하지 않았습니다.
